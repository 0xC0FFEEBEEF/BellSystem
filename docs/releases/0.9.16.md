SchoolBell 0.9.16 fixes delayed and missing transcripts, renews published bell schedules automatically, and adds classroom notification controls and centralized client logs.

### Fixed

- Recorded announcements enter the transcription queue as soon as upload finishes, instead of waiting for the 24-hour delivery window to close.
- Startup recovers interrupted transcription jobs and queues retained recordings that have no transcription job. Empty responses and timeouts retry with backoff.
- Final transcripts take priority over live previews. Quiet recognition input receives bounded gain; stored recordings and playback volume stay unchanged.
- History refreshes open transcripts and shows queued, running, retrying and failed work. Classroom transcript windows retain completed text when playback ends.
- Transcription performance settings show model readiness, queue counts, job duration, errors and available runtime CPU/thread information.

### Added

- Published bell schedules renew daily and after server outages from a snapshot of their published rules, calendar and sounds. Saved edits still require Publish.
- **Admin → Settings → Bell notifications** can turn bell cards off or set their duration from 1 to 300 seconds. The default remains 12 seconds.
- **Admin → Client logs** shows verbose SchoolBell service, companion, enrollment, installer and updater logs, with all-endpoint or single-endpoint filtering, search, paging, text downloads and a separate-window link. Uploads resume after outages; server retention is 14 days.
- **History → Transcript → Notify endpoints** resends a completed schoolwide transcript notification with View/Ignore to connected computers in the original audience. It does not replay audio or rerun recognition. History reports offline and outdated clients separately.

### Updating

Update the server first, then roll out the matching Windows client. Automatic renewal and the transcription queue repairs work with existing clients; the new notification and client-log features require the updated Windows service and companion.

On upgrade, a legacy published schedule adopts matching saved rules. If they differ, Bells → Calendar & publish shows a renewal warning: explicitly publish the intended schedule once. Targeted transcripts remain office-only.

### Validation

- 170 server tests and 86 client tests passed.
- Windows projects and the production web UI built successfully.
- The supplied 21.52-second recording was recognized locally by the bundled small.en model in 6.412 seconds using four CPU threads. This is a local smoke test, not a timing guarantee for other hardware or recordings.
- Release artifacts include signed manifests and SHA-256 checksums. Whisper binaries are checked for Ubuntu 24.04 compatibility.

The Windows installer is not Authenticode-signed. Its integrity is protected by the signed SchoolBell release manifest and published SHA-256 checksums.
